De la donnée à la décision

Trois étapes pour passer d'une liste de faits à un plan d'action

Veille

56 outils interrogent en parallèle le DNS public, les journaux de certificats, les archives du web, les bases de réputation et d'exposition. Sur demande, un rescan périodique signale ce qui a changé : nouveau sous-domaine, certificat qui expire, politique DMARC modifiée.

Analyse

La gravité n'est pas laissée à l'IA : 43 règles déterministes la fixent à partir des données brutes. Une CVE citée mais non observée est retirée ; une CVE exploitée activement (catalogue CISA KEV) passe en critique. Chaque preuve est confrontée à la donnée d'origine.

Intelligence

Pour chaque constat : les techniques MITRE ATT&CK qu'il rend possibles, les mitigations associées, une chaîne d'attaque plausible et des recommandations ancrées dans les référentiels (OWASP, ANSSI, RFC, Mozilla TLS).

Ce qui est analysé

Une vue d'ensemble de votre surface d'exposition publique

Messagerie

SPF, DKIM, DMARC, MTA-STS, TLS-RPT, BIMI : la capacité d'un tiers à usurper vos emails.

TLS et certificats

Validité, expiration, protocoles et suites acceptés, CAA, DANE, journaux Certificate Transparency.

Sous-domaines

Découverte, résolution de chaque nom, hôtes vivants, CNAME orphelins exposés au détournement.

Web et en-têtes

HSTS, CSP, cookies (Secure, HttpOnly, SameSite), technologies détectées, redirections.

Infrastructure

DNS, DNSSEC, IP, ASN, hébergeur et CDN, ports et CVE connus via Shodan InternetDB.

Réputation

Listes de blocage DNS, Safe Browsing, PhishTank, URLhaus, classement Tranco.

Fuites

Adresses présentes dans des fuites connues, fichiers sensibles archivés, secrets publiés sur GitHub.

Usurpation

Domaines imitant votre marque (typosquatting), en particulier ceux qui reçoivent déjà des emails.

Sécurité et confidentialité

Vos résultats ne sont lisibles qu'avec votre code

À la fin de l'analyse, le rapport et les données sont chiffrés avec une clé dérivée de votre code d'accès. Le serveur ne conserve pas ce code : sans lui, même l'administrateur ne peut pas relire le contenu.

  • Code de 256 bits, valable 30 jours, révocable. Envoyé seul par email : aucune pièce jointe.
  • Chiffrement AES-256-GCM des résultats en base, clé dérivée du code (HKDF).
  • Purge automatique des résultats et de votre identité 7 jours après expiration ou révocation du code.
  • Anti-abus : vérification anti-robot, code de vérification par email, limites de débit.
  • Strictement passif : requêtes DNS, sources publiques, et une visite de la page d'accueil comme le ferait un navigateur. Rien de plus.

Questions fréquentes

Ce qu'il faut savoir avant de lancer une analyse

Que signifie « reconnaissance passive » ?

ReconIA ne collecte que des informations déjà publiques : enregistrements DNS, journaux de certificats, archives du web, bases de réputation et d'exposition (par exemple Shodan InternetDB). Le seul contact direct avec votre site est celui d'un visiteur ordinaire : la page d'accueil est chargée et la négociation TLS observée. Aucun scan de ports, aucune force brute, aucune tentative d'exploitation.

Dois-je être propriétaire du domaine ?

Oui, ou disposer de l'autorisation explicite de son propriétaire. Même si les données sont publiques, le rapport les assemble dans un contexte de sécurité : il est destiné à la personne responsable du domaine.

Comment est-ce que je consulte mon rapport ?

Quand l'analyse est terminée, vous recevez un email contenant un code d'accès. Saisissez-le sur la page Voir le résultat : vous y consultez le rapport et le téléchargez en PDF, JSON, CSV ou en layer ATT&CK Navigator. Le code est valable 30 jours.

Qui peut lire mes résultats ?

Vous seul, avec votre code. Les résultats sont chiffrés en base avec une clé dérivée de ce code, que le serveur ne conserve pas. L'administrateur ne voit que des métadonnées (statut, durée, score) et les données techniques publiques collectées sur le domaine.

J'ai perdu mon code ou il a expiré : que faire ?

Le code ne peut pas être récupéré, il n'est stocké nulle part. Écrivez à contact@idachallenge.bj : l'administrateur peut émettre un nouveau code tant que les résultats n'ont pas été purgés, ou vous pouvez relancer une analyse.

L'IA peut-elle se tromper ?

Oui, c'est pourquoi elle est encadrée. La sévérité est fixée par des règles et non par le modèle, les CVE non observées sont retirées, chaque constat indique l'outil qui l'a prouvé et sa preuve est confrontée à la donnée brute. Un rapport reste un point de départ pour vos équipes, pas un audit.
